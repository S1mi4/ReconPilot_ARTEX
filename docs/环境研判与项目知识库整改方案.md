# 环境研判与项目知识库整改方案：从「每任务重推拓扑」到「项目级环境档案 + 证据化知识库」

> 背景：ARTEX 现在的"网络区域"是**读时算出来的标签**（`db/task_scope.go::coverageZone`：私网 IP→internal、公网域名→internet、有 URL 的服务→boundary），只服务于覆盖度图的配色和 asset_mapper 的一段叙述；它不落库、不分项目、不区分"经网关暴露"和"原生公网暴露"，也不参与漏洞判定。结果是：每个任务都要让 LLM 重新讲一遍拓扑，讲完就丢；同一项目里第二个任务对认证方式、网关行为、内网可达性的认识从零开始；`facts`/`task_intelligence` 都绑在任务/探索上，任务结束知识就死。本方案把这块补成三层：**环境档案（是什么）→ 前置研判（怎么确认）→ 项目知识库（记住并复用）**。

## 0. 现状（代码事实，不是印象）

| 能力 | 现状 | 位置 |
|---|---|---|
| 网络区域 | 读时启发式，三档 internet/boundary/internal，不落库 | `db/task_scope.go::coverageZone` |
| 拓扑叙述 | 按任务点一次，产出一段对话报告，不结构化、不被消费 | `server/task_asset_mapping.go`（asset_mapper） |
| 区域语义 | 已写进提示词，agent 被要求遵守三档含义 | `agent/promptcatalog.go:23,34` |
| 任务事实 | 探索节点 `kind='fact'`，绑探索（任务），跨任务不复用 | `exploration_nodes` |
| 任务情报 | `task_intelligence(kind=credential/lead/sensitive_data)`，绑任务 | `db/intelligence.go` |
| 项目级共享 | 只有资产库 / 企业 / 拦截规则 / 提示词（提示词是全局的） | `assets`、`companies` |
| 授权边界 | `task_scope(kind=company/root_domain/subdomain/ip/cidr/icp/keyword)` | `task_scope` |
| 高影响动作 | 提案 + 审批 + 人工执行回填（已落地） | `finding_escalations` |

三处结构性缺口：

1. **暴露面是"边"不是"点"**：`/api/admin` 挂在公网网关后面和它被 SSRF 打到内网，是两个完全不同的风险；现在两者都只是一个带 `url` 的 endpoint 节点。
2. **架构知识无处安放**：nginx / K8s ingress / API 网关 / WAF / 4A-SSO / 跳板机，这些决定"打进去能摸到什么"，现在只能靠 LLM 每轮现猜。
3. **知识不沉淀**：跨任务的只有资产坐标；"这个站是 SSO、那个接口要 mTLS、内网 10.0.0.0/8 不可直连"这类结论每次重学。

## 1. 目标与不变量

1. **档案描述"是什么"，不授予"能不能打"**。授权仍然只由 `task_scope` + 人工声明决定。知识库任何一条记录都不能扩大测试范围——这是本方案最容易出事的点，必须写进代码注释和 UI 文案。
2. **无证据不入库**：任何区域划分、网关识别、认证判定都必须能指回证据（资产行、流量 id、响应头、证书、人工声明）。没有证据的只能记为 `unknown`，不能默认成 `internal`（把对外暴露误判成内网，比反过来危险得多）。
3. **不确定要显式**：`unknown` 是一等公民。档案里长期保留"未确认项清单"，注入给 agent 时明确标注"这是未知，可以验证但不可以假设"。
4. **内网主动探测不因"已登记为内网"而获得许可**：主动打内网仍是 L2/L3 动作，走提案审批（沿用 `finding_escalations`）。被动推断（读已有资产/流量/证书）不受限。
5. **注入有预算**：planner 每轮最多 600 tokens 的环境摘要，wiki 只给索引，正文按需拉。禁止把整份档案塞进提示词。
6. **项目隔离**：所有新表 `project_id NOT NULL` + `ON DELETE CASCADE`，与既有分层一致；查询一律经项目上下文（`resolveProjectID`）。
7. **可复审**：档案有 revision 与 `reviewed_at`，超过 TTL 自动标记 stale，注入时带"上次确认于 N 天前"。

## 2. 问题拆解：四个具体失效场景

| 场景 | 现在的行为 | 后果 |
|---|---|---|
| A. 同一站点有两个入口（公网网关 + 内网直连） | 只有一个 endpoint 节点，zone 取地址判定 | 外/内暴露分不清，severity 与"利用前置条件"判错 |
| B. 网关（Kong/APISIX/ingress）后面挂了 20 个应用 | 20 个 endpoint 各自成节点，无人知道它们共用一个入口与一套鉴权 | 重复测认证、漏测路由级越权；blast radius 写错 |
| C. 第二、三个任务 | facts 从空开始 | 重复探测、重复否定结论、报告口径不一致 |
| D. 内网资产出现在答案里 | 私网 IP 一律 internal，agent 直接派探测意图 | 越权打内网（范围外），或把不可达地址当可达 |

## 3. 领域模型

```
项目 Project
 ├── 环境档案 EnvironmentProfile（每项目一份，带 revision）
 │    ├── 网络域 Zone（internet / dmz / office / intranet / cloud_vpc / lab / unknown）
 │    │     · 地址与域名集合、是否可主动探测（authorized）、备注
 │    ├── 入口 Entry（gateway / waf / ingress / lb / api_gateway / sso / jump_host / direct）
 │    │     · 所在 zone、host:port、路由前缀、上游 zone、认证方式
 │    └── 暴露关系 AssetExposure（资产 × 入口 → external/internal/both/unknown + 可达方式 + 证据）
 └── 知识库 Wiki
      ├── 页面 Page（overview/network/auth/api/tech/conventions/gotchas）
      ├── 条目 Claim（原子陈述 + 证据引用 + 置信度 + 状态 + TTL）
      └── 版本 Revision
```

三层的关系：**Zone/Entry/Exposure 是机器可判定的事实层**（尽量确定性计算），**Claim/Page 是解释层**（可以 LLM 起草，但必须引用事实层证据并等人确认），**观测 Observation 是研判的中间产物**（提案、待确认、被否）。

## 4. 数据模型（DDL）

> 位置约束：`projects` 表在 `db/schema.sql` 第 ~1818 行才创建，所有 FK 引用 `projects(id)` 的新表必须放在它之后（本项目 schema 是整份幂等重放，放错位置会让整份 apply 中断——上一轮 `finding_escalations` 踩过这个坑）。

```sql
-- 项目环境档案：一项目一份，rev 递增，人确认后才算"权威"。
CREATE TABLE IF NOT EXISTS project_environments (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL UNIQUE REFERENCES projects(id) ON DELETE CASCADE,
    -- single=单一公网入口 / dmz=公网+DMZ+内网 / hybrid=多入口混合 / internal_only=纯内网靶场 / unknown
    mode          TEXT NOT NULL DEFAULT 'unknown'
                  CHECK (mode IN ('single','dmz','hybrid','internal_only','unknown')),
    summary       TEXT NOT NULL DEFAULT '',      -- 一句话：这套环境大概长什么样
    revision      INT  NOT NULL DEFAULT 0,
    confirmed_by  TEXT NOT NULL DEFAULT '',
    confirmed_at  TIMESTAMPTZ,
    reviewed_at   TIMESTAMPTZ,                   -- 最近一次人工/自动复审
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 网络域。authorized 表示"允许主动探测该域"，与 task_scope 取交集后才真正生效。
CREATE TABLE IF NOT EXISTS network_zones (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    zone_key      TEXT NOT NULL,                 -- 稳定标识，如 internet / dmz / office / k8s-vpc
    kind          TEXT NOT NULL DEFAULT 'unknown'
                  CHECK (kind IN ('internet','dmz','office','intranet','cloud_vpc','lab','unknown')),
    label         TEXT NOT NULL DEFAULT '',
    cidrs         CIDR[] NOT NULL DEFAULT '{}',
    domains       TEXT[] NOT NULL DEFAULT '{}',
    authorized    BOOLEAN NOT NULL DEFAULT false, -- 只表达"项目是否登记为可探测"，不替代 task_scope
    source        TEXT NOT NULL DEFAULT 'declared'
                  CHECK (source IN ('declared','derived')),
    confidence    TEXT NOT NULL DEFAULT 'observed'
                  CHECK (confidence IN ('observed','inferred','unknown')),
    evidence      JSONB NOT NULL DEFAULT '[]',    -- [{type:'asset'|'traffic'|'human'|'dns', ref:'...'}]
    notes         TEXT NOT NULL DEFAULT '',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (project_id, zone_key)
);

-- 入口/网关。一个入口可以承载多个应用（path 前缀），也是"外/内"判定的关键。
CREATE TABLE IF NOT EXISTS service_entries (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    zone_id       BIGINT REFERENCES network_zones(id) ON DELETE SET NULL,
    kind          TEXT NOT NULL DEFAULT 'direct'
                  CHECK (kind IN ('gateway','waf','ingress','lb','api_gateway','sso','jump_host','direct')),
    product       TEXT NOT NULL DEFAULT '',       -- nginx / kong / apisix / traefik / envoy / 阿里云SLB ...
    host          TEXT NOT NULL,
    port          INT  CHECK (port BETWEEN 1 AND 65535),
    path_prefixes TEXT[] NOT NULL DEFAULT '{}',   -- /api /admin /gw ...
    upstream_zone_ids BIGINT[] NOT NULL DEFAULT '{}',
    auth_kind     TEXT NOT NULL DEFAULT 'unknown'
                  CHECK (auth_kind IN ('none','basic','form','jwt','oauth2','sso','mtls','unknown')),
    source        TEXT NOT NULL DEFAULT 'derived'
                  CHECK (source IN ('declared','derived')),
    confidence    TEXT NOT NULL DEFAULT 'inferred'
                  CHECK (confidence IN ('observed','inferred','unknown')),
    evidence      JSONB NOT NULL DEFAULT '[]',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_service_entries_project ON service_entries(project_id, host);

-- 暴露关系：一个资产经哪个入口暴露、暴露给谁。外/内是"边"的属性。
CREATE TABLE IF NOT EXISTS asset_exposure (
    asset_id      BIGINT NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
    entry_id      BIGINT REFERENCES service_entries(id) ON DELETE CASCADE,
    project_id    BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    exposure      TEXT NOT NULL DEFAULT 'unknown'
                  CHECK (exposure IN ('external','internal','both','unknown')),
    reachability  TEXT NOT NULL DEFAULT 'unknown'
                  CHECK (reachability IN ('direct','via_gateway','via_proxy','via_ssrf','unknown')),
    evidence      JSONB NOT NULL DEFAULT '[]',
    confidence    TEXT NOT NULL DEFAULT 'inferred'
                  CHECK (confidence IN ('observed','inferred','unknown')),
    last_seen     TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (asset_id, entry_id)
);
CREATE INDEX IF NOT EXISTS idx_asset_exposure_project ON asset_exposure(project_id, exposure);

-- 研判观测：中间产物 + 待确认结论 + 被否结论。"未知清单"就存在这里。
CREATE TABLE IF NOT EXISTS environment_observations (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    topic         TEXT NOT NULL
                  CHECK (topic IN ('zone','entry','auth','tech','egress','waf','scope','other')),
    statement     TEXT NOT NULL,
    basis         JSONB NOT NULL DEFAULT '[]',
    confidence    TEXT NOT NULL DEFAULT 'inferred'
                  CHECK (confidence IN ('observed','inferred','unknown')),
    status        TEXT NOT NULL DEFAULT 'proposed'
                  CHECK (status IN ('proposed','confirmed','rejected','stale')),
    decided_by    TEXT NOT NULL DEFAULT '',
    decided_at    TIMESTAMPTZ,
    expires_at    TIMESTAMPTZ,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_env_obs_pending ON environment_observations(project_id, status, created_at DESC);
-- 同一句话不重复堆：问卷式重复研判只更新行。
CREATE UNIQUE INDEX IF NOT EXISTS uq_env_obs_statement
    ON environment_observations(project_id, topic, md5(statement));

-- 知识库页面
CREATE TABLE IF NOT EXISTS wiki_pages (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    slug          TEXT NOT NULL,
    title         TEXT NOT NULL,
    kind          TEXT NOT NULL DEFAULT 'overview'
                  CHECK (kind IN ('overview','network','auth','api','tech','conventions','gotchas')),
    body_md       TEXT NOT NULL DEFAULT '',
    status        TEXT NOT NULL DEFAULT 'draft'
                  CHECK (status IN ('draft','confirmed','stale','archived')),
    revision      INT  NOT NULL DEFAULT 1,
    updated_by    TEXT NOT NULL DEFAULT '',
    reviewed_at   TIMESTAMPTZ,
    env_revision  INT  NOT NULL DEFAULT 0,        -- 写这份页面时依据的环境档案版本
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (project_id, slug)
);

-- 原子条目：agent 引用的是条目，不是整页正文。条目必须带证据。
CREATE TABLE IF NOT EXISTS wiki_claims (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    page_id       BIGINT NOT NULL REFERENCES wiki_pages(id) ON DELETE CASCADE,
    claim         TEXT NOT NULL,
    -- [{type:'asset'|'traffic'|'finding'|'human'|'observation', ref:'...'}]
    evidence      JSONB NOT NULL DEFAULT '[]',
    confidence    TEXT NOT NULL DEFAULT 'inferred'
                  CHECK (confidence IN ('observed','inferred','unknown')),
    status        TEXT NOT NULL DEFAULT 'proposed'
                  CHECK (status IN ('proposed','confirmed','refuted','stale')),
    proposed_by   TEXT NOT NULL DEFAULT '',       -- agent key 或 human
    verified_by   TEXT NOT NULL DEFAULT '',
    verified_at   TIMESTAMPTZ,
    ttl_days      INT NOT NULL DEFAULT 90,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_wiki_claims_page ON wiki_claims(page_id, status, id DESC);

-- 版本历史（与 agent_prompts 同构：只追加，不覆盖历史）
CREATE TABLE IF NOT EXISTS wiki_revisions (
    id            BIGSERIAL PRIMARY KEY,
    page_id       BIGINT NOT NULL REFERENCES wiki_pages(id) ON DELETE CASCADE,
    revision      INT  NOT NULL,
    body_md       TEXT NOT NULL,
    note          TEXT NOT NULL DEFAULT '',
    updated_by    TEXT NOT NULL DEFAULT '',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (page_id, revision)
);

-- findings 上补两个快照列：判定时看到的暴露/架构，避免事后无法复盘"当时依据什么定的级"。
ALTER TABLE findings ADD COLUMN IF NOT EXISTS exposure_snapshot JSONB NOT NULL DEFAULT '{}'::jsonb;
```

设计取舍：

- **不为每个资产加 `zone` 列**，因为一个资产可能同时有多个入口（公网 + 内网），单列表达不了。`asset_exposure` 是主模型，覆盖度图查询时用 `LEFT JOIN` 取"最外暴露"做展示（并保留现有 `coverageZone` 作为无档案时的兜底）。
- **`service_entries` 与 `network_zones` 不合并**：入口是"边界上的具体设备/配置"，域是"地址集合"。一个域可以有多个入口，一个入口可以终结到多个域。
- **`wiki_claims` 与 `environment_observations` 不合并**：前者是"要长期复用的知识"（可能来自历史任务、人工、代码审计），后者是"这次研判得出的待确认结论"。混在一起会让"哪些还需要人确认"变模糊。

## 5. 前置环境研判流程（S0–S6）

目标：**1 分钟人工声明 + 全自动被动归集 + 少量待确认问题**，产出可复用的档案。每一步独立可重跑、幂等、可只跑一段。

### S0 声明（人工，可选但强烈建议）
在项目设置里填：目标域名/主体、已知内网网段、网关产品与所在层、认证方式（SSO/OAuth/JWT/无）、禁区（不许打的内网段/域名）。
产出：`network_zones(source=declared)` + `project_environments.mode/summary`。
**声明优先于推断**：声明过的 zone 不被自动研判覆盖。

### S1 被动归集（确定性，无 LLM）
数据源：`assets`（domain/ip/port/url/technologies/status_code/page_title/auth）、`traffic`（host/url_template/path/status/content_type）、证书 SAN（若已采集）、DNS 记录。
产出候选表：host → (ports, titles, tech, cert, first_seen)。纯 SQL，可在几千行规模下秒级完成。

### S2 网关/路由识别（规则优先，LLM 只解歧义）
信号（任一强信号即可判"同一入口"）：
- 同一 `ip:port` 上多个不同 `url_template` 前缀（`/app1 /app2 /api`）；
- 同一主机一族统一 `server` 头（nginx/openresty/kong/apisix/tengine/envoy/traefik）；
- 存在 `x-request-id` / `x-envoy-*` / `x-cache` / `via` 等代理特征；
- 多域名共用同一张证书（SAN 多值）或同一 IP；
- 错误页/默认页指纹一致（400/413/502 页面）；
- 认证重定向统一（都 302 到同一个 `/login` 或 IdP）。

弱信号组合交给 LLM 判"是不是同一个入口"，**但只允许在候选集合内选，不允许创造新主机**；结论写 `environment_observations(topic=entry, status=proposed)`。

### S3 外/内暴露判定（确定性优先）
见 §6 算法。产出 `asset_exposure`，`unknown` 允许且常见。

### S4 认证体系识别
证据：401/302 模式、`WWW-Authenticate`、cookie 名（`JSESSIONID` / `SESSION` / `Authorization` JWT 结构）、SSO 跳转链、mTLS 握手失败特征、默认口令页。产出 `service_entries.auth_kind` + observations。

### S5 收敛与人工确认
- LLM 起草 `wiki_pages(draft)`：overview / network / auth / api 四页起步，正文**只能引用已存在的 claims 与 observations**。
- 每条 claim 带 `evidence`；缺口列成 observations（即"未知清单"）。
- 人在 UI 里逐条确认/否决（批量确认支持"OK，全部接受"）。

### S6 复审与失效
- `project_environments.reviewed_at` + TTL（默认 90 天）→ 过期标 `stale`，注入时带"上次确认于 N 天前，建议复查"。
- 触发复审：新增域、新增网关特征、新任务发现与档案冲突的证据、人工点"重新研判"。
- 冲突处理（如流量证明某"内网"地址公网可达）：**新增 observation 并降级原结论**，不静默改写。

## 6. 外/内暴露判定算法

对每个资产 A、入口 E：

```
exposure(A, E) =
  external   若 E.zone.kind = internet|dmz 且 E 有公网可达证据（流量/资产 url/证书）
  internal   若 A 只能通过 非公网入口（jump_host/内网直连/SSRF 路径）到达
  both       两个方向都有证据
  unknown    证据不足（默认）
```

硬规则（按顺序）：

1. **地址不是判据**：私网 IP 有公网 URL/流量证据 → `external`（例如云上 172.16 段经 SLB 暴露）。
2. **公网主机上的 path 不等于 external**：`/internal-debug` 若被网关规则挡住（403/404 由网关返回），记 `internal`，证据是"网关返回"。
3. **可达性优先于声明**：声明为内网但有流量来自互联网端口 → 升级为 `external` 并生成冲突 observation。
4. **无证据不给 internal**：给 `unknown`。理由：把外部暴露误判为内网，会让人以为"打不到"，是漏判；反过来只是多测。
5. **SSRF 视角单独算**：`reachability=via_ssrf` 是"从漏洞点能到达"，不是"公网可访问"，报告中必须区分。

判定结果同时用于：
- 覆盖度图着色（替换现有读时启发式，保留兜底）；
- 漏洞判定的前置条件描述（"该接口经 gw-01 暴露于互联网，需登录态"）；
- 提案的 `blast_radius` 自动补全（"落地在 dmz 的 gw-01，上游可达 intranet 的 10.0.0.0/8"）。

## 7. LLM Wiki：结构与生命周期

**页面（人读的叙述）**

| slug | 内容 | 典型来源 |
|---|---|---|
| `overview` | 这几个系统是什么、测什么、禁区 | 人工 + 任务发现 |
| `network` | 域划分、入口清单、可达关系 | S1–S3 |
| `auth` | 认证体系、账号来源、越权测试约定 | S4 + 历史任务 |
| `api` | 接口地图（谁调谁、外部/内部分界）、版本前缀 | 流量 + 资产 |
| `tech` | 技术栈/框架/中间件/版本 | 资产 + 指纹 |
| `conventions` | 测试约定：命名、可用的测试账号、限速、报告口径 | 人工 |
| `gotchas` | 坑：WAF 会拦、某些接口一碰就告警、某账号会锁 | 历史任务 |

**条目（agent 引用的原子断言）**

```json
{"claim":"后台 /admin 与门户 /portal 共用同一套 SSO（Keycloak，realm=corp）",
 "evidence":[{"type":"traffic","ref":"12345"},{"type":"entry","ref":"7"}],
 "confidence":"observed","status":"confirmed","ttl_days":90}
```

**状态机（与提案系统同构，agent 不能自我授权）**

```
proposed ──(人确认)──> confirmed ──(过期/冲突)──> stale
    └──(人否决)──> refuted
```

**硬规则**

1. agent 只能写 `proposed`；`confirmed` 只有人（或系统对纯事实类、如"资产 X 的端口是 443"）能写。
2. 每条 `confirmed` claim 必须有非空 `evidence`；空证据一律降级为 `proposed`。
3. 页面正文不单独承载"事实"，事实都在 claims 里；正文是它们的组织方式。这样 agent 引用时能精确到句子。
4. 冲突不覆盖：同一 slug 同一主题出现矛盾 claim → 两条都保留，状态都降为 `proposed`，并在 UI 里成对展示让人裁决。
5. 删除靠 `archived`，历史可查。

## 8. 消费层：注入预算与工具

| 消费者 | 注入内容 | 预算 |
|---|---|---|
| planner（每轮） | 环境摘要：mode、zone 列表（含 authorized）、入口 Top-N、**未知项 Top-3**、revision/年龄 | ≤ 600 tokens |
| worker（每次领意图） | 只注入该意图资产所属 zone 的切片 + 相关 claims（≤5 条） | ≤ 200 tokens |
| asset_mapper | 整份档案 + 冲突项（它本来就是梳理拓扑的） | 不限（对话内） |
| 漏洞详情 | 该 finding 资产的 exposure 链 + 相关 claims | 展示用 |
| 报告生成 | 引用 claims 时带 slug#claim，可追溯 | — |

工具（都只读，除 `wiki_propose`）：

```json
{"name":"env_profile",
 "desc":"读取本项目环境档案：域、入口、某资产的暴露链。params: zone? asset_id? entry_id?",
 "schema":{"zone":{"type":"string"},"asset_id":{"type":"integer"},"entry_id":{"type":"integer"}}}

{"name":"wiki_search",
 "desc":"在项目知识库中检索条目（不是全文：返回 claim + 证据引用 + 状态）。params: q, kind?, status?",
 "schema":{"q":{"type":"string"},"kind":{"type":"string"},"status":{"type":"string"}}}

{"name":"wiki_read",
 "desc":"读取一个 wiki 页面的正文与它的条目列表。params: slug",
 "schema":{"slug":{"type":"string"}}}

{"name":"wiki_propose",
 "desc":"把一条观察写成待确认的知识条目（draft claim），必须给证据。人确认后才会进入 confirmed。",
 "schema":{"slug":{"type":"string"},"claim":{"type":"string"},
           "evidence":{"type":"array"},"confidence":{"type":"string"}}}
```

注入实现点：

- `agent/tools.go::graphOverviewData` 增加 `environment` 字段（摘要），复用现有"整包塞进 planner 提示"的通道，无需新机制。
- `agent/prompt.go` 的 code-owned 块（与 `minimalExploitBlock` 同级）加一段**允许稳定注入**的说明：环境摘要可能不完整，"未知"不等于"不存在"，冲突以现场证据为准。这段由代码持有，DB 覆盖提示词也丢不掉。
- worker 侧在构造意图上下文时按资产过滤（`ToolSet` 已有 `taskID`/资产锚定能力）。

## 9. 与既有能力的关系（不重复造）

| 既有 | 本方案怎么用 |
|---|---|
| `coverageZone` | 保留为"无档案时的兜底"；有档案后以 `asset_exposure` 为准，UI 标注来源 |
| asset_mapper | 从"每次重讲一遍"改成"档案的叙述者"：输入整份档案，输出页面正文与待确认条目 |
| `task_scope` | 授权唯一来源。`network_zones.authorized` 只表示"项目登记为可探测"，实际探测还要 `task_scope` 覆盖 |
| `finding_escalations` | 内网主动探测、跨域跳转探测仍走提案；提案的 `blast_radius` 用档案自动补全 |
| `task_intelligence` | 不动。任务级情报继续留在任务内；只有当它上升为"项目公共知识"时才由人/agent 提 `wiki_propose` |
| `facts` | 不动。跨任务复用通过 wiki claim，而不是把 facts 提升成全局（facts 是探索证据，wiki 是稳定结论） |

## 10. 判定准确性改进（用户关心的"判得更准"）

1. **暴露度参与判级上下文**：`report_finding` 增加可选 `entry_id`/`exposure`，服务端用档案校验并写入 `findings.exposure_snapshot`。severity **不自动改**，但详情页、报告、审批页都会显示"互联网可达 / 需内网立足点"。理由：自动改级会把模型的判断替换成规则的判断，而规则的证据常常是缺的。
2. **前置条件必答**：内网类发现（SSRF、RCE 回连）必须说明"从哪到哪"，档案缺失时提示补研判，而不是猜。
3. **跨任务去重**：`wiki_claims(conventions/gotchas)` + 既有 findings 指纹，让 planner 在派意图前就知道"这条路上一轮走过了、结论是否定且证据充分"。
4. **报告口径统一**：报告里网络部分只引用档案与 claims，不再让生成器自由发挥拓扑。
5. **冲突显式化**：档案与现场证据冲突时，先出 observation，再改结论，留痕。

## 11. UI

1. **项目设置 → 环境档案**：域/入口/暴露三张表，可编辑；每行显示来源与置信度；顶部"待确认 N 项"。
2. **项目设置 → 知识库**：页面列表 + 逐条 claim 的确认/否决；"重新研判"按钮；stale 徽章。
3. **任务页顶部横幅**：`环境：dmz · 3 个入口 · 档案 32 天前确认（建议复查）`，点开抽屉看摘要。
4. **覆盖度图**：节点着色改用 `asset_exposure`（无档案则兜底），新增"经入口"连线。
5. **漏洞详情**：暴露链 + 相关 claims（当前"利用验证"Tab 旁边再加一段，不新开 Tab）。
6. **审批页**：`blast_radius` 自动补全的字段标"系统补全"，与 agent 原文区分。

## 12. 阶段计划

### P0（基础，1 次提交，不含 LLM）
- schema：4 张表 + `asset_exposure` + `findings.exposure_snapshot`。
- 确定性暴露计算（`db/environment.go`）：从资产/流量算出 zone 候选、入口候选、exposure，`source=derived`。
- `env_profile` 只读工具 + `graphOverviewData` 注入摘要（≤600 tokens，只在有数据时注入）。
- 项目设置页只读展示 + "重新计算"按钮。
- 验收：注入空档案时不改变现有 planner 行为；有数据时 planner 提示里能看到域/入口/未知项。

### P1（研判流程 + 知识库读写）
- S0 声明表单、S1–S5 流水线（job 化，可重跑）、observations 确认 UI。
- `wiki_pages/wiki_claims` 读写 API + 页面；`wiki_search`/`wiki_read` 工具。
- asset_mapper 改为档案叙述者。
- 验收：一个新项目从 0 到"能回答这套环境长什么样"≤ 5 分钟人工介入；未知项必须显式列出。

### P2（写入与复用）
- `wiki_propose` 工具（worker/planner/pentest）、claim 状态机、TTL/stale、冲突成对展示。
- 跨任务去重（planner 提示里带"已否定的方向 Top-N"）。
- `report_finding` 的 `entry_id/exposure` + 暴露链展示 + 提案 blast_radius 自动补全。
- 验收：第二个任务在同一项目里不再重复探测已确认的认证方式；冲突场景（私网 IP 公网可达）产生 observation 且不静默改写。

### P3（架构模板与运营）
- 部署模板预设：nginx 反代 / K8s ingress / API 网关 / WAF+SSO / 跳板机，选择后自动套用识别信号与 prompt 片段。
- 档案健康度：完整度评分、过期提醒、按项目统计"因缺少档案导致的 unknown 判定数"。
- 导出：环境档案 + 知识库进报告附录。

## 13. 风险与取舍

1. **LLM 幻觉写进知识库**：只有 `proposed` 能被 agent 写；`confirmed` 必须人工或有硬证据；注入时带 status，agent 被要求"confirmed 才可作前提"。
2. **知识过期比没有更危险**：TTL + stale 标注 + 引用时带 `reviewed_at`；报告里引用过期条目必须显式声明。
3. **误判"内网"导致漏判**：算法层面禁止无证据给 internal（见 §6 第 4 条），UI 上 unknown 与 internal 用不同颜色。
4. **上下文膨胀**：硬预算 + 索引/拉取两段式；超预算时优先保留"未知项"和"与当前意图相关"的切片。
5. **越权探测**：档案不授予权限（§1 第 1 条）；内网主动探测走提案；`network_zones.authorized` 与 `task_scope` 双闸。
6. **运维成本**：S0 声明是唯一强制的 1 分钟人工步骤；其余全自动，宁可多列 unknown 也不要求人填满。
7. **多项目串味**：所有查询走项目上下文；wiki 不允许跨项目引用（哪怕同一企业）。

## 14. 需要拍板的决策点

1. 环境档案粒度：**每项目一份**（推荐，符合"环境属于项目"的实际）还是每任务一份？
2. 内网主动探测：**默认必须提案**（推荐，与既有安全模型一致）还是 zone 授权后可直接探？
3. agent 写知识库：**只能写 proposed**（推荐）还是允许直接写 confirmed（仅限技术栈这类事实）？
4. 判级是否自动用暴露度调整 severity：**只做上下文与展示**（推荐）还是自动升降级？
5. 注入预算：planner 每轮 **≤600 tokens**（推荐）是否可接受？
6. 知识库初始内容：**从历史 findings/任务自动生成草稿**（推荐，省人力但可能带噪声）还是完全从零人工写？
